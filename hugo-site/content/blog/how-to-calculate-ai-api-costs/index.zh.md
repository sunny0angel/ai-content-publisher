每一个活过生产环境的 AI 应用，最终都会面对同一张表格：一次 API 调用到底花多少钱？这个问题看起来简单，但大多数团队都会答错——不是因为算术难，而是定价模型的可变因素太多，直觉会失灵。一个预估每月 $500 推理费用、最后收到 $4,300 账单的团队，通常犯了三种错误之一：token 数算错了，忽略了输入输出的价格差，或者以为列表价就是实际支付价。

本指南给出精确的计算方法，使用 2026 年 8 月 OpenAI GPT-5.6 系列与 DeepSeek V4 系列的官方列表价，附完整算例，并说明如何把计算变成预算纪律。想跳过理论直接跑数字，可以用免费的 [AI Token 与 API 费用计算器](/zh/tools/ai-token-cost-calculator/)，全程在浏览器内完成。

## 为什么 API 成本估算总是失准

先看原因，再看公式。成本超支大多可以归入三种失败模式：

**1. token 数按错误的基数估算。** 用原型阶段的「平均请求大小」做预算，上线时提示词却长了五倍——系统指令、工具 schema、检索上下文、对话历史。输入里多出来的每一个 token，之后每一次请求都会被计费，永久有效。

**2. 输入和输出的价格完全不同。** 在 GPT-5.6 Sol 上，输出 token 的价格是输入的 6 倍（每百万 $30 对 $5）。生成长输出的应用——报告、代码、翻译——成本由输出主导；把文档塞进上下文的 RAG 应用则由输入主导。给两者套用同一个混合单价，正是估算偏差 3–5 倍的来源。

**3. 忽略了缓存、批量和档位。** OpenAI 对重复前缀提供自动提示词缓存折扣，DeepSeek 对缓存命中提供优惠价，双方都奖励批量处理。列表价是起点，不是账单。

## 核心公式

一次 API 调用的费用是：

```
费用 = (输入 token ÷ 1,000,000 × 输入单价)
     + (输出 token ÷ 1,000,000 × 输出单价)
```

单价以每百万 token 计价。公式不难，难的是往里面填准确的数字。下面逐项拆解。

### 第一步：把 token 数算对

用字符数除以 4 就收工是不行的——这个近似对英文散文误差在 ±10–30%，但中文、日文和代码的偏差要大得多。分词器把文本切成子词单元，一个中文字符往往就是一个 token，而一个英文单词通常是 1.3–1.5 个 token。

获得精确值的三种方式：

- **OpenAI**：`tiktoken` 库，使用与模型匹配的编码（GPT-5.6 级别用 `o200k_base`）
- **Anthropic**：`claude-tokenizer` 包，或 API 的 `count_tokens` 端点
- **DeepSeek**：API 文档中的分词器端点

实用经验值：中英混合文本按**字符数 ÷ 3.5**，代码为主的请求按**字符数 ÷ 2.5** 做预算。但在任何基础设施承诺之前，务必用真实分词器重新测量。

### 第三步：算一个实例

以客服聊天机器人为例：系统提示词 2,000 token，检索上下文 1,500 token，用户消息 300 token，平均回复 400 token。用 GPT-5.6 Luna（经济档）计算：

```
输入  = 2,000 + 1,500 + 300 = 3,800 token
输出  = 400 token
费用  = (3,800 ÷ 100万 × $0.20) + (400 ÷ 100万 × $1.20)
      = $0.00076 + $0.00048
      = 每次请求 $0.00124
```

每天 10,000 次对话，就是每天 $12.40，**每月约 $372**（Luna）。同样的负载用 Sol 跑，每月 $4,650——还没做任何提示词优化，仅价格档位选择就差了 12.5 倍。这就是为什么模型选择是你最该花心思的成本决策。

## 真正有效的四个成本杠杆

成本控制不是逐个抠 token，而是结构性选择。按影响从大到小：

**1. 模型档位选择（10–100 倍）。** Sol 与 Luna 的差距、Sol 与 DeepSeek V4 Flash 的差距，碾压其他所有杠杆。简单任务路由到便宜模型，前沿模型留给真正需要的任务。多模型路由已成为大规模运行 AI 团队的标准做法（见[开源 AI 与闭源 AI 分析](/zh/blog/open-source-vs-proprietary-ai-market-shift-2026/)）。

**2. 提示词缓存（不同服务商折扣 50–90% 不等）。** OpenAI 与 DeepSeek 自动缓存跨请求重复的输入前缀，缓存命中按低于完整输入价计费；Anthropic 的缓存读取约为标准输入价的 10%。把系统提示词和检索上下文固定放在请求开头，命中率最高。

**3. 批量处理（省 25–50%）。** OpenAI Batch API 和 DeepSeek 批量价对可等待 24 小时的负载提供折扣。分类任务、数据回填、评测作业大多不需要实时响应。

**4. 控制输出长度（2–10 倍）。** 设置 `max_tokens`、使用结构化输出模式、要求简洁回答。输出是 OpenAI 系模型最贵的 token，削减输出的收益是双份的：少计费 + 低延迟。

## 建立预算模型

经得起生产检验的预算，每个功能需要三个数字：请求量、token 结构（输入输出比）、模型档位。用表格管理：

| 功能 | 请求/天 | 输入 token | 输出 token | 模型 | 每月费用 |
|------|---------|-----------|-----------|------|---------|
| 客服机器人 | 10,000 | 3,800 | 400 | Luna | 约 $372 |
| 文档摘要 | 500 | 12,000 | 1,500 | Terra | 约 $240 |
| 代码审查 | 2,000 | 8,000 | 2,000 | Sol | 约 $3,720 |

让人不安的通常是最后一行。当单个功能主导预算时，把它路由到更便宜的档位或开源权重模型，回报最大。

用 [Token 费用计算器](/zh/tools/ai-token-cost-calculator/)直接试验这些数字——粘贴真实请求体，切换模型，看月度预测如何变化。最后记得乘以 1.3：没有任何团队能避免第一季度的流量低估。

## 针对具体负载估算 token 数

每种负载都有特征性的 token 结构。了解你自己的结构，是「估算」和「瞎猜」的分界线。以下是实测应用的典型结构：

| 负载 | 典型输入 | 典型输出 | 主导侧 |
|------|---------|---------|--------|
| 客服聊天（RAG） | 3,000–6,000 | 200–600 | 输入 |
| 文档问答（大语料） | 8,000–30,000 | 300–800 | 输入 |
| 摘要 | 8,000–30,000 | 500–1,500 | 输出 |
| 代码生成 | 2,000–10,000 | 800–3,000 | 输出 |
| 翻译 | 2,000–15,000 | 约等于输入 | 均衡 |
| Agent 循环（函数调用） | 每步 3,000–8,000 | 每步 200–800 | 输入 × 步数 |

把结构变成可用预算，靠三条纪律：

1. **先测量，再估算。** 把真实提示词交给官方分词器跑一次，把数字记进定价用的同一张表。测量的动作本身会推翻所有假设。
2. **在生产环境记录 token。** 每个请求都记录 API 响应里的 `prompt_tokens` 和 `completion_tokens`。服务商每次都返回，记录它们零成本，猜测就变成了时间序列。
3. **对漂移设置告警。** 提示词改版多加了 2,000 token，diff 里没人注意得到。一张「每请求平均 token」的周报图表几秒就能发现。输出长度同理——一个开始用项目符号写小说的模型，会在任何人看日志之前把你的账单翻倍。

## 折扣层：缓存、批量与档位

列表价是上限，不是账单。三种机制会把它打折，这笔账值得算一次：

**提示词缓存。** 服务商会缓存跨请求重复的输入前缀。前缀完全一致即命中：OpenAI 对符合条件的缓存输入 token 按折扣计费（长提示词历史上为 50%），Anthropic 的缓存读取约为标准输入价的 10%，DeepSeek 的缓存命中价远低于它本已很低的输入价。一个 4,000 token 的系统+上下文前缀，每天重复 10,000 次，按全价就是每天 4,000 万输入 token。这个前缀享受 50–90% 折扣，往往就是所有可选项中省得最多的单项——而且除了让前缀逐字节保持一致，不需要任何提示词工程。

**批量 API。** OpenAI Batch API 和 DeepSeek 批量价对可等待 24 小时的负载把列表价砍掉约一半。分类回填、夜间 embedding、评测套件、报告生成是典型候选。

**吞吐档位与承诺。** 两家服务商都为持续负载提供承诺用量和预留吞吐定价。这需要合同承诺，只在你有三个月真实用量数据之后才值得谈——过早签约会把错误数字锁死。

实践顺序：先改提示词结构（缓存免费），再把符合条件的任务迁到批量（改一次 API），最后才谈档位（签合同）。

## 从原型到 100 万次请求：预算推演

假设一个产品从每天 10,000 次请求起步，输入 4,000 token、输出 500 token，跑在 GPT-5.6 Luna 上：

```
单次请求费用 = (4,000 ÷ 100万 × $0.20) + (500 ÷ 100万 × $1.20)
            = $0.0008 + $0.0006 = $0.0014
每月费用     = $0.0014 × 10,000 × 30 ≈ $420
```

半年后流量涨到 5 倍，每天 50,000 次请求。诚实的预测是**每月 $2,100**——成本线性增长，这是计量推理最不舒服的性质。现在按顺序应用杠杆：

1. **把 60% 流量**（简单问答）路由到 DeepSeek V4 Flash（$0.14/$0.28）：这部分从约 $1,260 降到约 $105
2. **缓存共享前缀**：留在 Luna 上的 40%，其 4,000 token 前缀打五折，再省约 $250
3. **夜间报告任务转批量**：再省 $60

同一个产品、同样的流量，从 $2,100 降到约 $700——三分之一。零提示词改动、一个路由决策。这就是整套纪律浓缩在一个例子里：**token 单价是供应商的事实，单次请求成本是工程的选择。**

## 预算落地：仪表盘、告警与价格战

没人看的成本模型一文不值。控制住 AI 账单的系统有四个共同习惯：

**按功能打用量标签。** OpenAI 允许给 API 请求附带元数据；Langfuse 和 Helicone（均为开源）跨服务商提供同样能力。给每个请求打上发起功能标签，成本仪表盘就不再是一个数字，而是一份成本中心排行榜。多数团队会发现：20 个功能里 2 个占了账单的 80%——不打标签就永远看不见这个事实。

**在 50 / 80 / 100% 处设预算告警。** 每家服务商控制台都支持用量告警，开源追踪器还叠加了异常检测。第一条告警要设在「还来得及行动」的位置。典型失败故事不是「我们没检查」，而是「我们在账单之后才检查」。

**看单价比看月度总额。** 每次对话、每份处理文档、每千 token 用户价值的成本——找一个随业务成功而增长的计量单位。产品增长带动月度总额上升是好消息；用量没变而总额上升是提示词的 bug。单价指标一眼就能区分这两种情况。

**按季度重新预测，因为价格只跌不涨。** 这是 2026 年市场的结构性事实：[中美价格差](/zh/blog/gpt-5.6-vs-deepseek-v4-pricing-2026/)在极端处高达 107 倍，中国开源权重模型把整个市场往下压，列表价每个季度都在跌。按今天的价格做的预算，半年后就是高估。这有两层含义——不要按今天的费率签长期承诺，并且每个季度重做一次模型选择决策。本季度「最便宜的正确答案」，未必是你上个季度默认的前沿模型。

还有一个稳赚不赔的习惯：把每次提示词改动连同 token 影响备注，记在一个纯文本文件里。成本回退和性能回退一样，几乎总是由一次善意的编辑引入。有了这个文件，「账单为什么暴涨」就从调查变成了查表。

## 账单术语小词典

服务商账单使用一套值得花一次时间学会的词汇，因为每个词背后都藏着一个成本决策：

- **Token** — 计费单位，一个子词片段，约等于 4 个英文字符
- **输入 / 输出 token** — 你发送的 token 与模型生成的 token。生成是逐 token 顺序执行，因此所有主流服务商的输出都更贵
- **上下文窗口** — 模型单次调用接受的最大输入。窗口越大能处理的文档越长，但每次调用都按完整输入计费——塞进 100K token 的 128K 上下文，比同任务的 4K 上下文贵 25 倍
- **缓存 token** — 服务商存储并再次计费的重复输入前缀 token，命中后按折扣价。把稳定前缀固定在提示词前端
- **批量价** — 可等待任务（OpenAI 最长 24 小时）的折扣费率。用延迟换约半价
- **TPM / RPM** — 每分钟 token / 请求数限流。不是成本本身，但决定花钱速度的上限，且更高档位对应不同价格
- **承诺用量 / 预留吞吐** — 折扣费率的合同容量。只有几个月稳定用量数据之后才值得签
- **微调费用** — 训练 token 与推理分开计费，加上模型存储。小规模微调便宜；人们常忘的是「微调模型按溢价单价持续推理」这项经常性成本

对照这张词典逐行读你的第一张账单，是找出那个不该存在的数字的最快方式——做过的团队无一例外都能找到一个。
