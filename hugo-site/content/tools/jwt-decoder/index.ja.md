JSON Web Tokenを貼り付けると、ヘッダー・ペイロード・署名が即座にデコードされ、`iat`／`exp` はローカル時刻に変換されて表示されます。トークンはブラウザ内に留まり、外部に送信されることはありません。

## JWTとは

JSON Web Tokenは、ドットで区切られた3つのBase64urlエンコード部分で構成されます。`header.payload.signature`。ヘッダーは署名アルゴリズム（`alg`）を宣言し、ペイロードはクレーム（`sub`、`exp`、`iss`、カスタムフィールド）を運び、署名は最初の2つの部分が改ざんされていないことをサーバーが検証するためにあります。

**重要**: デコードは検証ではありません。JWTは誰でもデコードできます——署名が真正性を証明するのは、正しい鍵と照合されたときだけです。このツールは意図的に検証しません。だから鍵が不要で、完全にオフラインで動きます。

## チェックポイント

- **`alg: "none"`** — 署名なしを宣言するトークン。本番環境では即座にレッドフラグです。バリデーターは拒否しなければなりません
- **過去の `exp`** — 期限切れトークン。サーバーは拒否します。クライアントが保持し続けているならリフレッシュフローが壊れています
- **過剰なクレーム** — トークンは必要最小限に。クレームが増えるほどトークンは肥大し、そのトークンは毎リクエスト送信されます
- **ペイロード内の秘密情報** — `password` や `api_key` クレームが入っているなら、誰かが認証と保存を混同しています

## 典型的な用途

401ループのデバッグ：トークンをデコードし、`exp` と `aud` を確認し、バックエンドが期待する鍵・発行者を特定する。[Base64エンコーダー](/ja/tools/base64-encoder/)（JWTは内部的にBase64url）と[SHAハッシュジェネレーター](/ja/tools/hash-generator/)（HS256＝HMAC-SHA-256）と自然に組み合わせられます。
