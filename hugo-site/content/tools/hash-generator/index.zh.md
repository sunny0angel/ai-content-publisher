在浏览器内为任意文本生成密码学哈希——SHA-256、SHA-512 或 SHA-1——使用浏览器内置的 Web Crypto API。数据不出本机，相同输入永远得到相同摘要。

## 工作原理

哈希函数把任意长度的输入映射为固定长度的摘要：SHA-256 是 256 位，SHA-512 是 512 位，SHA-1 是 160 位。输出是确定性的（相同输入→相同摘要）、单向的（不可逆推）、具有雪崩效应（改动一个字符，约一半输出位会变化）。

计算在 `crypto.subtle`——浏览器硬件支持的密码学引擎——上执行，不涉及任何第三方库。

## 算法选择

| 算法 | 摘要长度 | 2026 年状态 | 用途 |
|------|---------|------------|------|
| SHA-256 | 256 位 | 标准 | 默认选择：校验和、指纹、签名、TLS、Git |
| SHA-512 | 512 位 | 标准 | 高保证场景；64 位 CPU 上比 SHA-256 更快 |
| SHA-1 | 160 位 | 安全用途已弃用 | 仅遗留兼容——新系统不要用 |

密码场景下这三者都不适用：应使用 Argon2 或 bcrypt 这类带盐的慢速函数。哈希服务于完整性，不是用来存秘密的。

## 常见用途

- **文件完整性**：用厂商公布的校验和验证下载
- **内容指纹**：检测重复文档和缓存条目
- **Git 与区块链**：SHA-256（Git 使用 SHA-1/SHA-256 系）支撑提交 ID 和区块
- **API 签名**：HMAC-SHA256 是请求签名与 Webhook 的标准

摘要需要在 JSON 请求体内传输时配合 [Base64 编码器](/zh/tools/base64-encoder/)，要查看令牌签名算法时配合 [JWT 解码器](/zh/tools/jwt-decoder/)。
